System Design for Data Engineering

A twelve-lesson course for someone starting from zero. By the end you will be able to design a data pipeline, defend the choices you made, and name what you traded away to make them.

Twelve lessons · start from zero

#How data gets from where it is made to where it is useful

Twelve lessons, eighteen diagrams and a practice quiz, taking you from "what is a data warehouse" to designing a pipeline and walking someone through its failure modes.

Start the course Jump to practice

#Who this is for

Someone who has heard the words — pipeline, warehouse, Kafka, dbt, idempotent — and does not yet have a structure to hang them on. No prior data engineering experience is assumed. Basic SQL helps but is not required for the reading; it becomes necessary at the practice stage.

The course teaches ideas rather than products. Tools are named so you recognise them in job descriptions and conversations, but the tools turn over every few years and the ideas do not.

#What you will be able to do

  • Explain why analytics does not run on the application's database, in terms of how bytes sit on disk
  • Choose an ingestion pattern for a source and defend it against the alternatives
  • Recognise a pipeline that will silently produce wrong data, and say which specific failure will cause it
  • Model a dataset into facts and dimensions with a clearly stated grain
  • Take a vague request and turn it into a design with numbers, trade-offs and failure modes attached

#The one idea to leave with

In backend engineering, the failure you fear is the system being down — loud, obvious, everyone knows within a minute.

In data engineering, the failure you fear is the system being wrong — silent, still reporting success every morning, and capable of running for weeks while people make decisions on the output. Almost every practice in this course exists because of that difference.

#How to use this site

  • Read in order the first time. Pages are sequenced by dependency, not importance, so later lessons assume earlier ones.
  • Tick topics off as you go. Every section has a Done checkbox and the sidebar tracks the whole course.
  • Search is fast. Press / anywhere to jump into the search box.
  • Do the exercises. Several lessons end with something to try on your own machine. Those are where the learning actually happens — reading about idempotency is not the same as breaking a pipeline and watching the row count double.
