Ten principles, condensed

  1. Keep raw data forever and never edit it.
  2. Make every write idempotent.
  3. Parameterise by logical date, never CURRENT_DATE.
  4. Partition by what you filter on.
  5. Prefer batch until a named decision forces otherwise.
  6. Test freshness, volume and uniqueness on everything that matters.
  7. Define business logic exactly once.
  8. Declare the grain before writing the query.
  9. Store both event time and ingestion time.
  10. Choose the simplest thing that meets the stated numeric requirement — then write down the trade-off you made.

Four books, in reading order

Read first

Fundamentals of Data Engineering

Reis & Housley. The best single overview of the field, and the closest thing to an expanded version of this course. Start here.

Reference

The Data Warehouse Toolkit

Kimball & Ross. The canonical text on dimensional modelling. Dense — read the first four chapters properly, then treat it as a lookup.

After you build

Designing Data-Intensive Applications

Kleppmann. The deep foundations: replication, partitioning, consistency, consensus, stream processing. Harder, and worth it — but read it once you have shipped something.

If you go deep

Streaming Systems

Akidau, Chernyak & Lax. The clearest treatment of event time and watermarks anywhere. Only when streaming becomes your problem.

Things to practise on

  • DuckDB — the best local sandbox for columnar analytics. No account, no cluster, no setup.
  • Public datasets — NYC TLC trip records, GH Archive, Wikipedia pageviews, or any large Kaggle set.
  • Documentation worth reading directly — dbt's guides on incremental models and testing; the Iceberg or Delta specification overview; Kafka's design documentation. Primary sources are consistently better than blog summaries in this field, because the summaries all copy each other.
